# Cross-Unet 比例实验与智能调配对比

## 实际执行的实验

本扩展使用 Cross-Unet-Ratio 项目交互轻量变体（787个可训练参数）。为在 GitHub Pages 浏览器CPU中训练，采用96→24点池化、多尺度24/12/6时序编码、未来条件交叉注意力（单头8维）、粗尺度跳跃连接、双输出残差及蒙尘单调门控。残差重复4步，与原15分钟物理先验结合。所有权重从随机初始化更新，不冻结骨干。不是原论文完整复现，也不是原16,062参数模型的比例重训；两者不作性能增量比较。

TensorFlow.js 4.22.0 / CPU，Adam 0.003，批量32，最大30轮，验证加权MSE选择权重。预先设定60/20/20、70/15/15、80/10/10，每个用42、123、2026三个种子共9次实际训练。浏览器自定义比例同一代码从头训练，可设10/30/60轮与种子；合计100%，每组10%–80%，至少42个目标日。默认推荐70/15/15。测试只在完成轮次选择后评价，学习曲线不显示逐轮测试。

生成器种子73021，421日组成420个目标日，2025-01-02至2026-02-25，历史96×8、未来96×6、目标96×2。按目标日期连续拆分；上一日已知观测可以作为下一日起报历史。同一训练集合内随机打乱日批次。固定物理尺度归一化，不用全数据均值方差。全部为公开逻辑的合成机理数据；NWP含约10%辐照系统偏差，污染先验与真值高度相关是合成设计假设，不是实地预报能力。

## 统计口径

全天加权损失：PV归一化MSE + 0.5×负荷归一化MSE。报告PV精度使用起报时预报辐照>20W/m²筛选，容量177.1kWp。nRMSE/nMAE是容量归一化，非MAPE。显示n、MAE、偏差、R²。每组保留充分统计量可以重新计算指标。7日循环移动块Bootstrap 1000次产生95%探索区间，捕捉部分日期相关性，但不能覆盖全部季节漂移。训练/验证指标区间不代表无偏泛化估计，验证还用于选轮次。

多种子表为算术均值±样本标准差（分母n−1），不是置信区间。各比例自己的测试日期不一致，因此另用共同末42日（2026-01-15至2026-02-25），所有允许比例均把该窗口留作测试。共同窗口是测试子集，不能重复计为独立样本；该比较仍改变了训练/验证季节和最优轮次，不是单因素因果实验。不要根据反复查看的测试结果选择比例；正式使用需要新的外部测试。

## 重现

```
npm install --no-save --package-lock=false @tensorflow/tfjs@4.22.0
node scripts/train-ratio-study.mjs
node scripts/verify-ratio-training.mjs
npm test
npm run build
```

源代码 `src/ratio-engine.mjs` 同时供Node预计算和浏览器WebWorker使用。运行库完整离线打包于src/vendor，保留Apache-2.0声明与许可证。数据、权重、学习曲线和元数据发布在data/cross-ratio-study.json。自定义结果仅保存在当前页面内存，可通过导出保存。CPU微小浮点差异可能因浏览器/运行时变化。

## 智能调配图表

在既有三个情景方案上，新增累计日运行成本、同设备增量贡献、充电/放电/弃光、峰时购电量及分时执行计划。购电费用减少+外送收入增加+吞吐费用减少=固定规则成本−滚动成本。电价0.30/0.65/1.00元/kWh，外送0.25元/kWh，吞吐0.035元/kWh。无储能比较含设备价值；规则/滚动使用相同设备，才能表述算法增量。

全部图表来自现有调配计算，不是独立优化器基准或实际生产效果。建议按成本差正负选择影子试验候选；峰时电量减少不必然降低最大需量，本模型不含需量电费、线路潮流、生产移峰或新增投资现金流。分时各电量和全天核算闭合。
